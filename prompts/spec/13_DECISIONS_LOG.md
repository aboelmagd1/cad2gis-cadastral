# CAD2GIS Specification — Document 13: Architectural Decisions and Conflict Log

> **ملخص باللغة العربية (Arabic Summary):**  
> يوثق هذا المستند السجل التاريخي والنهائي لقرارات المالك المعمارية (D01 إلى D20) ومصفوفة فض النزاعات الـ 11 المذكورة في الملحق ب (Appendix B)، وتحديد العناصر المفتوحة (OPEN Items) التي تتطلب تأكيداً إضافياً من المالك مع تحديد السلوك الافتراضي المعتمد مرحلياً. يمثل هذا السجل المرجع المعتمد لمنع التضارب بين متطلبات ملفات التوجيه القديمة والكود الفعلي القائم.

## 1. Owner Decision Register (Appendix A)

| ID | Date | Subject | Decision Summary | Rationale & Impact | Supersedes |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **D01** | 2026-03-01 | Platform & Toolchain | ArcGIS Pro 3.3.0 Add-in (.NET 8.0, C#) with ArcPy fallback sharing `HelperFiles`. | Target framework `net8.0-windows` for Add-in, `net8.0` for Core. No legacy .NET Framework 4.8. | Earlier ArcMap / Pro 2.x references |
| **D02** | 2026-04-10 | Source Mode Strategy | Strictly **two source options per step**: (1) Previous Step live output, (2) User Own Data. | Eliminates synchronization ambiguity and duplicate disks copies. "Latest export" source mode is abolished. | Multi-source radio selectors, legacy export-sync |
| **D03** | 2026-04-12 | Output Delivery | **Exactly one primary output per step** added to the active map with layer name matching feature class. Step 5 produces 4 deliverables. | Eliminates map clutter, prevents memory leaks, and ensures clear step progression. | Multiple redundant scratch layers on map |
| **D04** | 2026-04-15 | Coordinate System | Mandatory projected UTM zones **35N–40N** (WGS 84, EPSG 32635–32640). All metric calculations in UTM meters; export GCS EPSG:4326 with frozen metrics. | High-precision municipal measurements; geographic coordinates only for final regulatory delivery. | Arbitrary local CRS / unprojected CAD processing |
| **D05** | 2026-04-18 | Geometry Integrity | **Zero geometry deformation** of working data: true circular arcs remain arcs. Controlled densification ($\le 0.001\text{ m}$) only for GCS/Shapefile export. | Retains surveying accuracy without introducing vertex drift. | Aggressive generalization / unconstrained densification |
| **D06** | 2026-04-20 | Parcel Construction | Three explicit modes: **Line**, **Polygon**, and **Line with data layer**. Line with data layer splits at vertices and attributes via 60% dominant boundary length. | Robust handling of legacy CAD layers where polygons are unclosed or linework holds classification. | Old "Polygon Line" ambiguous mode |
| **D07** | 2026-04-22 | Step 1 Layer UI | Dynamic, refreshable per-layer USAGE dropdown populated directly from `Usage Types` Excel sheet. | Allows operator to classify CAD layers directly during ingestion without manual attribute editing. | Hard-coded layer classification lists |
| **D08** | 2026-04-25 | USAGE Precedence | 4-tier precedence: Manual edit > Valid Excel match > Layer USAGE > Fallback. Strict 6 codes: `RSD, COM, RSC, AGR, IND, UTL`. | Prevents invalid land-use codes; `PLT` is strictly a Border Type, not a parcel Usage Type. | Prompts stating `USAGE = PLT` |
| **D09** | 2026-04-28 | REMARKS Field | Content: Chosen usage text > USAGE > Empty. Never `PlotId`, never provenance debugging text. | Keeps municipal land-use remarks clean and compliant with survey standards. | Auto-populating CAD filename or PlotId into REMARKS |
| **D10** | 2026-05-02 | PLOT_ID Ingestion | `PLOT_ID` comes exclusively from `[Text & Annotations]` layers. In Line with data layer mode, Step 3 pulls from Step 2 `PLOT_TXT`. | Ensures parcel identification is decoupled from geometry layers and driven by surveyed text annotations. | Using arbitrary block attributes or layer names |
| **D11** | 2026-05-08 | Border Decomposition | Borders extracted only for MAIN parcels; max 4 single-part lines per ring (1 North, 2 East, 3 South, 4 West); independent rings; interior angle split $[10^\circ, 160^\circ]$ & $[200^\circ, 350^\circ]$; $7\text{ m}$ corner clusters. | Produces clean 4-facade municipal cadastral records; handles chamfered street corners without orphan vertices. | Multi-part lines, splitting without clustering |
| **D12** | 2026-05-12 | Shared Segments | Coincidence buffer $0.05\text{ m}$, minimum overlap $\ge 0.5\text{ m}$. MAIN neighbour = `PLT`; SUB neighbour = `BorderType_Keywords.csv` match; no neighbour = street/passage. | Precise neighbor identification; automatically labels common parcel party walls as `PLT`. | Using parcel bounding box overlaps |
| **D13** | 2026-05-15 | Street Width Sensing | Single ray from midpoint as primary default (3-ray median optional). Facing obstacle parcel $\ge 1.0\text{ m}$ away, $\le 100.0\text{ m}$. $10.0\text{ m}$ passage threshold. | Fast, predictable street corridor measurement without ray fan intersection anomalies. | 3-ray median mandatory default; automatic snapping |
| **D14** | 2026-05-18 | DIMENSION Attribute | `DIMENSION` = `Single` if all segment deflection angles $\le 15^\circ$; otherwise `Multi`. One true arc is treated as a single segment. | Standardizes facade linearity reporting for municipal approval. | Arbitrary vertex count or $20^\circ$ deflection threshold |
| **D15** | 2026-05-20 | Field Naming & DBF | Description field name resolved from template (`DESCRIPTO` primary, `DESCRIPTIO` fallback). DBF string lengths validated in UTF-8 bytes. | Prevents silent truncation or DBF export failure for Arabic multi-byte strings. | Fixed 10-char truncate without byte check |
| **D16** | 2026-05-22 | Runtime Lookups | All official code lists read from `Required Fields in the Shapefile.xlsx` at runtime. Zero hard-coded lists. | Guarantees compliance when municipal authority updates standard codes without needing code recompilation. | Hard-coded C# enum code lists |
| **D17** | 2026-05-25 | HelperFiles Layout | Central `HelperFiles/` next to active Pro project with self-healing fallback to install directory. Support multiple consultant profiles. | Seamless portability between client workstations and deployment environments. | Hard-coded `C:\` developer file paths |
| **D18** | 2026-05-28 | Border Performance | Spatial index over parcel envelopes, cached buffers, lazy obstacle candidate filtering, throttled progress dispatching. | Enables decomposition of 5,000+ parcels in under 60 seconds without UI freeze. | Unindexed pairwise spatial intersects |
| **D19** | 2026-06-01 | Anti-Freeze Threading | No sync-over-async (`.Result`, `.Wait()`) on UI thread; Pro API SDK calls dispatched via `QueuedTask.Run`; SHA-256 data stamps. | Complete UI responsiveness; robust change detection immune to Windows file folder timestamp jitter. | Blocking UI thread during geoprocessing |
| **D20** | 2026-06-05 | Arabic & xArab Fonts | Bilingual UI (Arabic/English); xArab decoding with slash preservation only between numeric digits (`11/3314`). | Correctly renders legacy reversed Arabic CAD text while preserving parcel subdivision slash numbers. | Corrupting parcel numbers with slash inversions |

## 2. Resolved Conflicts Matrix (Appendix B)

| Ref # | Conflicting Statements | Precedence Applied | Authoritative Resolution | Spec & Code Status |
| :--- | :--- | :--- | :--- | :--- |
| **C01** | **Latest-export source mode vs. Two-option rule**<br>Earlier prompts described a 3rd source option ("Latest Export") that polled disk folders. | Owner D02 (Tier 1) | **Resolved:** Exactly two source options per step: (1) Previous Step, (2) User Own Data. Exported outputs become the live working data. | Spec: `02_PIPELINE`, `10_UI`<br>Code: `IMPLEMENTED` |
| **C02** | **3-ray median default vs. Single-ray default**<br>Earlier Step 4 prompt specified 3-ray fan median as default; Owner D13 mandated single ray midpoint default. | Owner D13 (Tier 1) | **Resolved:** Single perpendicular ray from segment midpoint is the default. 3-ray median is preserved as a user-configurable toggle in Settings. | Spec: `06_STEP4`, `09_SETTINGS`<br>Code: `IMPLEMENTED` |
| **C03** | **`USAGE = PLT` vs. `Usage Types` sheet**<br>An early business-rules prompt suggested marking main parcels with `USAGE = 'PLT'`. | Owner D08 & Excel (Tier 1 & 2) | **Resolved:** `PLT` is strictly a `BORDERTYPE` code (denoting a neighboring parcel boundary). Parcel `USAGE` must strictly be one of `RSD, COM, RSC, AGR, IND, UTL`. | Spec: `05_STEP3`, `08_DATA`<br>Code: `IMPLEMENTED` |
| **C04** | **Interior-Angle Threshold & DIMENSION Angle**<br>Prompts differed between $20^\circ$–$130^\circ$ vs $10^\circ$–$160^\circ$ for split points, and $20^\circ$ vs $15^\circ$ for `DIMENSION`. | Owner D11, D14 & Code (Tier 1 & 3) | **Resolved:** Split point interior angle range is $[10^\circ, 160^\circ]$ and reflex mirror $[200^\circ, 350^\circ]$. `DIMENSION` threshold is $15^\circ$ deflection. | Spec: `06_STEP4`, `08_DATA`<br>Code: `IMPLEMENTED` |
| **C05** | **`DESCRIPTIO` vs. `DESCRIPTO` & Code Spellings**<br>Field name length conflicts (10-char DBF limit); typos in prompts (`MSD` vs `MSQ`, `PAK` vs `PRK`). | Owner D15, Excel `Border Types` | **Resolved:** Template-driven field name resolution: primary `DESCRIPTO`, fallback `DESCRIPTIO`. Border codes strictly from Excel (`MSQ` for Mosque, `PRK` for Park, `WCH` for Watchroom). | Spec: `06_STEP4`, `08_DATA`<br>Code: `IMPLEMENTED` |
| **C06** | **HelperFiles Paths (`C:\` vs Project Relative)**<br>Old prompts hard-coded paths like `C:\CAD2GIS\HelperFiles`. | Owner D17 (Tier 1) | **Resolved:** Dynamic 3-tier discovery: (1) Active Pro Project root `HelperFiles/`, (2) User Profile directory, (3) Embedded fallback in Add-in installation directory. | Spec: `09_SETTINGS`<br>Code: `IMPLEMENTED` |
| **C07** | **Final Shapefile Folder & Export Toggles**<br>Dispute whether shapefiles reside in `Final/` or `Final/Shape/`; whether shapefile export is optional. | Owner D03 (Tier 1) | **Resolved:** Step 5 mandatory outputs are always produced (both FileGDB and Shapefile). Interim path default is `Final/Shape/` subfolder. | Spec: `02_PIPELINE`, `07_STEP5`<br>Code: `IMPLEMENTED` |
| **C08** | **`PARCEL_TYP` vs Working `_CLASS` Field**<br>Confusion whether `_CLASS` (`MAIN`/`SUB`) is an official municipal attribute. | Owner D03, D06 & Schema (Tier 1 & 2) | **Resolved:** `_CLASS` is an internal working field present only in Step 2. In Step 3, official MOMRAH field is `PARCEL_TYP` (Code from `Building Types`). Working fields are purged in Step 3 output. | Spec: `02_PIPELINE`, `05_STEP3`<br>Code: `IMPLEMENTED` |
| **C09** | **Step Numbering Mismatch (UI vs Code)**<br>In legacy code, Step 3 method was named `ExecuteStep3Async` but performed border extraction (UI Step 4). | Code Refactoring (Tier 3) | **Resolved:** Spec strictly standardizes on UI 5-Step Pipeline: Step 1 (Layers), Step 2 (Parcels), Step 3 (Attributes/Schema), Step 4 (Borders), Step 5 (Export/QA). Code partial rename mapped. | Spec: `02_PIPELINE`<br>Code: `PARTIAL` (mapped in Status Matrix) |
| **C10** | **`BorderType_Keywords.csv` vs Usage / Provenance in REMARKS**<br>Older prompts mixed land-use keywords into border CSV and wrote provenance strings to `REMARKS`. | Owner D09, D12, D16 | **Resolved:** `BorderType_Keywords.csv` maps text strictly to border codes; `Usage_Keywords.csv` maps to land-use codes. `REMARKS` contains only land-use text, never provenance. | Spec: `05_STEP3`, `08_DATA`<br>Code: `IMPLEMENTED` |
| **C11** | **Outdated Class & Field References in Legacy Prompts**<br>Old prompts referred to nonexistent classes (`CadLayerExtractor`, `ArcPyBridgeService`) or fields (`PARCEL_ID`). | Local Active Code (Tier 3) | **Resolved:** Authoritative names verified against active repository: `GdbFeatureClassService`, `PipelineStateManager`, `QaValidationEngine`, official field `PARCEL_NO`. | Spec: `00_SOURCES`, `08_DATA`<br>Code: `IMPLEMENTED` |
